# Anchorage Fourplex Prospector

A standalone, auditable prospecting tool for Municipality of Anchorage parcels recorded with exactly four living units. It downloads public assessment records from the ArcGIS service behind the Municipality's Property Information map, filters by minimum ownership duration, and calculates a transparent opportunity score.

This project is intentionally separate from the auction scraper and Property Underwriter.

## Private web application

The repository now includes an authenticated Next.js dashboard designed for Vercel. It queries the public Anchorage ArcGIS service on the server, caches results for one hour, and does not commit generated owner/property datasets. Configure `SITE_PASSWORD` and `AUTH_SECRET` as Vercel environment variables before deployment.

```powershell
pnpm install
pnpm dev
```

The dashboard provides ranked prospects, conservative owner portfolios, filters, property details, evidence links, and a visible scoring method. This password gate is intended for a small private deployment; use a full identity provider and database-backed authorization before granting access to a larger team.

## What it produces

- `all_fourplexes.csv` — every current parcel returned with four living units.
- `fourplex_prospects.csv` — properties meeting the ownership-duration threshold, ranked by score.
- `owner_portfolios.csv` — normalized owner groups, fourplex counts, units, assessed value, and portfolio signals.
- `run_summary.json` — counts, source URL, retrieval timestamp, cutoff date, and scoring version.
- `fourplex_prospects.xlsx` — formatted review workbook (generated by the included workbook builder when the Codex artifact runtime is available).

Raw exports contain owner names and mailing addresses. Keep them private and use them only for lawful real-estate research and outreach. The `outputs/` directory is ignored by Git.

## Quick start

Python 3.11+ is sufficient; the extractor uses only the standard library.

```powershell
python -m anchorage_fourplex --output-dir outputs/latest
```

From a source checkout without installing:

```powershell
$env:PYTHONPATH = "src"
python -m anchorage_fourplex --output-dir outputs/latest
```

Useful options:

```text
--minimum-years-owned 20   Minimum apparent ownership duration (default 20)
--as-of YYYY-MM-DD         Scoring date (default: today)
--include-geometry         Include parcel centroid coordinates
--timeout 60               HTTP timeout in seconds
```

## Method

The downloader first requests all matching ArcGIS object IDs, then retrieves records in bounded chunks. The base query is:

```sql
Total_Living_Units = 4 AND GIS_Category = 'Parcel'
```

`Deed_Date` is used as the apparent acquisition date. A deed date is a screening indicator—not a complete ownership history. Trust, estate, entity, or intra-family transfers can reset it. Recorder research is required before treating ownership duration as confirmed.

The score is deliberately explainable:

| Signal | Points |
|---|---:|
| Owned 20–24 years | 20 |
| Owned 25–34 years | 30 |
| Owned 35+ years | 40 |
| Mailing address differs from property | 15 |
| Mailing state is outside Alaska | 20 |
| Owner appears to be an individual/estate/trust | 10 |
| Building built 1979 or earlier | 15 |
| Building built 1980–1989 | 10 |
| Building built 1990–1999 | 5 |
| Same normalized owner has 2 fourplex parcels | 5 |
| Same normalized owner has 3–4 fourplex parcels | 10 |
| Same normalized owner has 5+ fourplex parcels | 15 |

Version 2 retains the original `Opportunity_Score` and adds `Enhanced_Opportunity_Score`, which includes the visible portfolio bonus and is capped at 100. Owner matching is deliberately conservative: names are normalized for punctuation, spacing, common legal suffixes, and trustee roles, but matches still require human verification. Portfolio counts cover fourplex parcels in this dataset—not every property an owner may control.

The output calls this an opportunity score, never a factual “tired owner” designation. Missing data earns no points and is exposed through quality flags.

## Limitations

- The service covers the Municipality of Anchorage, not only the Anchorage Bowl.
- Unit count and deed date are assessor fields and may be incomplete or lag real-world changes.
- Absentee status is inferred by comparing normalized property and mailing addresses.
- Tax delinquency, code violations, probate, permits, refinancing, rents, and full deed-chain verification require additional authorized sources and are not guessed.
- Scores rank public-record signals; they are not claims about an owner's motivation, condition, finances, or willingness to sell.
- Normalized names can still create false matches or miss related entities; beneficial ownership requires corporate or recorder enrichment.
